# TracertMap — трассировка маршрута на карте мира

Десктопная программа на Python, которая повторяет работу утилиты `tracert`
и показывает каждый узел маршрута на интерактивной карте мира.

Два режима работы:

1. **Живая трассировка** — вводите IP-адрес или домен, программа сама отправляет
   ICMP-запросы с растущим TTL (как `tracert`), определяет местоположение каждого
   ответившего маршрутизатора и рисует путь на карте по мере прохождения.
2. **Построение по готовой трассировке** — вставляете (или открываете файлом) вывод
   `tracert` / `traceroute` / `tracepath` / `mtr`, а программа разбирает его и строит маршрут.

## Возможности

- Собственная реализация трассировки:
  - **Windows** — через системный ICMP API (`iphlpapi.dll`), тот же механизм, что у `tracert.exe`.
    Работает **без прав администратора**.
  - **Linux** — непривилегированные ping-сокеты или raw-сокеты (root); **macOS** — raw-сокеты.
  - Если встроенный движок недоступен, автоматически запускается системный `tracert` / `traceroute` /
    `tracepath`, а его вывод разбирается «на лету».
- Параллельный опрос нескольких TTL — трассировка в разы быстрее, чем у `tracert`
  (значение «Параллельно: 1» даёт классическое поведение).
- Остановка после N молчащих узлов подряд (узел назначения блокирует ICMP — не ждать до 30-го прыжка).
- Подложки без API-ключа: OpenStreetMap, улицы / топографическая / спутник Esri. Маршрут — дугами
  большого круга, корректный переход через 180-й меридиан, цвет узлов и отрезков по задержке.
  Подписи над точками с контрастной обводкой; на спутнике — светлые.
- Таблица узлов, вывод в формате `tracert`, панель подробностей (провайдер, AS, координаты,
  расстояние от старта).
- **Проверка геолокации физикой**: если узел отвечает быстрее, чем свет в оптоволокне успел бы
  дойти до его «официального» местоположения и обратно, он помечается знаком ⚠.
- Частные адреса (`192.168.x.x`, `10.x.x.x`, CGNAT `100.64.x.x`) показываются рядом с предыдущим
  известным узлом (в начале маршрута — в точке старта).
- Разбор готовых трассировок: Windows (русская и английская), Linux/macOS `traceroute`
  (в т.ч. несколько адресов на одном TTL), `tracepath`, `mtr --report`, просто список IP;
  кодировки UTF-8, UTF-16 (PowerShell `> file.txt`), cp866 (cmd.exe), cp1251.
- Сохранение в JSON (можно открыть снова), TXT в стиле `tracert`, CSV для Excel,
  экспорт в самостоятельную **HTML-карту** (Leaflet) для отчёта или отправки.
- Кэш геолокации на диске, лимиты бесплатных API соблюдаются автоматически.
- Свой внешний IP (точка старта) обновляется кнопкой «Обновить IP» (F6), перед каждой трассировкой
  и автоматически при смене сети — например, при включении или выключении VPN.
- Надёжный ввод адреса: можно вставить ссылку (`https://ya.ru/…`), `ya.ru:443`, кириллический домен;
  если системный DNS не отвечает (бывает с VPN-клиентами), имя разрешается через публичные DNS.

## Установка и запуск

Нужен **Python 3.9+** с tkinter (в Windows он входит в стандартный установщик с python.org).

### Windows

Дважды щёлкните `run.bat` — при первом запуске он сам установит зависимости.
Или вручную:

```bat
pip install -r requirements.txt
python main.py
```

Файл `TracertMap.pyw` запускает программу без консольного окна.

### Linux / macOS

```bash
sudo apt install python3-tk        # Debian/Ubuntu, если tkinter ещё нет
pip install -r requirements.txt
python3 main.py                    # или ./run.sh
```

В большинстве современных дистрибутивов Linux непривилегированные ICMP-сокеты уже разрешены.
Если нет — программа автоматически переключится на системный `traceroute` (`sudo apt install traceroute`), либо
разрешите ping-сокеты: `sudo sysctl -w net.ipv4.ping_group_range="0 2147483647"`.

### Параметры командной строки

```text
python main.py ya.ru                     # открыть окно и сразу начать трассировку
python main.py -f samples/tracert_windows_ru.txt   # открыть готовую трассировку
python main.py --cli ya.ru               # консольный режим без окна (как tracert)
python main.py --cli -f trace.txt        # разобрать файл и вывести в формате tracert
```

## Как пользоваться

1. **Трассировка.** Введите адрес в поле «Узел назначения» и нажмите «Трассировать» (Enter / F5).
   Узлы появляются в таблице и на карте по мере ответа. «Стоп» (Esc) прерывает трассировку.
   Если имя не удалось разрешить, в сообщении об ошибке указана причина для каждого способа.
2. **Готовая трассировка.** Кнопка «Построить по готовой трассировке…» (Ctrl+O): вставьте текст,
   откройте файл или нажмите «Пример». Флажок «выполнена с этого компьютера» определяет, откуда
   начинается маршрут на карте.
3. **Изучение маршрута.** Щелчок по строке таблицы или маркеру на карте показывает подробности
   и центрирует карту; двойной щелчок — приближение. Если в одной точке карты несколько узлов
   (например, все маршрутизаторы одного города), повторные щелчки по маркеру переключают их.
   Правый щелчок по строке: копировать IP, трассировать до этого узла, сведения об IP на bgp.he.net.
4. **Сохранение.** «Сохранить…» (Ctrl+S) — JSON / TXT / CSV / HTML; «HTML-карта» (Ctrl+E)
   сохраняет и сразу открывает интерактивную карту в браузере.

Настройки: «Макс. прыжков», «Таймаут», «Запросов» на узел — как у `tracert`;
«Параллельно» — сколько TTL опрашивать одновременно; «Стоп после пустых» — 0 отключает;
«Метод» — Авто / встроенный ICMP / системная утилита; «DNS-имена узлов» — обратное разрешение имён.
Меню «Геолокация» — источник данных (ip-api.com, ipwho.is или локальная база `.mmdb`), язык названий,
повтор геолокации, обновление своего IP и очистка кэша. Ваш IP и город показаны справа в строке
состояния, рядом кнопка «Обновить IP».

## Как это работает

```
 Компьютер ──TTL=1──▶ Роутер 1  ✖ TTL=0 → «Time Exceeded» от Роутера 1   → узел №1
 Компьютер ──TTL=2──▶ Роутер 1 ─▶ Роутер 2 ✖ → «Time Exceeded» от Роутера 2 → узел №2
 …
 Компьютер ──TTL=N──▶ … ─────────────────▶ Узел назначения → «Echo Reply»  → конец
```

Каждый маршрутизатор уменьшает TTL пакета на единицу и, получив пакет с TTL = 0, отбрасывает его
и отвечает ICMP-сообщением «Time Exceeded» — так становится известен его адрес и время
«туда-обратно». Строка `* * *` означает, что узел не ответил (часто это фильтрация ICMP, а не обрыв).

| Движок | ОС | Права | Протоколы |
|---|---|---|---|
| ICMP API `iphlpapi.dll` | Windows | обычный пользователь | IPv4 |
| ping-сокет + `IP_RECVERR` | Linux | обычный пользователь* | IPv4 |
| raw-сокет | Linux, macOS | root / `CAP_NET_RAW` | IPv4, IPv6 |
| системная утилита | все | обычный пользователь | IPv4, IPv6 |

\* если разрешено `net.ipv4.ping_group_range` (по умолчанию в большинстве дистрибутивов).

Перед трассировкой встроенный движок проверяет себя запросом к `127.0.0.1`; при сбое в режиме
«Авто» программа переключается на системную утилиту.

## Геолокация: что важно знать

- **ip-api.com** (по умолчанию) — до 100 адресов в одном запросе, 15 запросов в минуту, без ключа;
  бесплатный вариант работает только по HTTP и только для некоммерческого использования.
- **ipwho.is** — HTTPS, без ключа, около 1000 запросов в сутки; используется и как запасной.
- **Локальная база `.mmdb`** — офлайн; нужен пакет `maxminddb` и файл GeoLite2-City (MaxMind)
  или DB-IP City Lite.
- Местоположение маршрутизаторов **приблизительное**: адреса магистральных узлов нередко «привязаны»
  к офису провайдера, а не к реальной точке. Поэтому есть проверка по скорости света (знак ⚠).
- Точка старта определяется по вашему внешнему IP **мимо системного прокси**: ICMP-пакеты
  трассировки через HTTP/SOCKS-прокси не идут, поэтому VPN-клиент в режиме «системный прокси»
  (v2rayN, Nekoray и т.п.) на маршрут не влияет — и старт показывается по реальному адресу.
  Полноценный VPN (WireGuard, OpenVPN, TUN-режим) меняет и маршрут, и точку старта.
- IP проверяется при запуске, перед каждой трассировкой, по кнопке «Обновить IP» и автоматически
  при смене сети (программа раз в 3 секунды бесплатно, без запросов в интернет, смотрит, через
  какой адаптер идёт трафик). Уже завершённый маршрут сохраняет точку старта, с которой он снят;
  для загруженной трассировки «с этого компьютера» старт обновляется.
- Если VPN-клиент подменяет DNS (FakeDNS, адреса `198.18.x.x`), программа замечает это и берёт
  настоящий адрес узла у публичного DNS (Яндекс 77.88.8.8, Google 8.8.8.8, Cloudflare 1.1.1.1),
  а при недоступности UDP — через DNS-over-HTTPS.
- Кэш хранится в `~/.tracertmap/geo_cache.json` (30 дней), настройки — в `~/.tracertmap/settings.json`.

## Структура проекта

```
main.py, TracertMap.pyw     точка входа (окно / консольный режим)
tracemap/
  engines.py                отправка ICMP с заданным TTL: Windows API, raw, ping-сокеты
  tracer.py                 цикл по TTL, выбор движка, запуск системной утилиты
  parser.py                 разбор tracert / traceroute / tracepath / mtr / JSON
  geo.py                    геолокация (ip-api, ipwho.is, .mmdb) и кэш
  geomath.py                расстояния, дуги большого круга, 180-й меридиан, скорость света
  route.py                  точки и отрезки маршрута для карты, группировка узлов
  exporters.py              JSON, TXT, CSV, HTML (Leaflet)
  dnsresolve.py             разрешение имён: очистка ввода, IDN, запасной DNS, FakeDNS
  models.py, netutil.py     модели данных, вспомогательные сетевые функции
  gui/app.py                главное окно (tkinter + tkintermapview)
  gui/load_dialog.py        диалог готовой трассировки
  gui/icons.py, settings.py маркеры карты, сохранение настроек
samples/                    примеры трассировок в разных форматах
tests/                      тесты (unittest) и эмулятор сети на TUN-интерфейсе
```

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты разбора, экспорта, геометрии и геолокации работают везде. Тесты движков на эмулированной
сети (`tests/netsim.py` — цепочка «маршрутизаторов» на TUN-интерфейсе) запускаются только в Linux
от root; остальные при этом пропускаются.

## Сборка .exe (необязательно)

`build_exe.bat` собирает `dist\TracertMap.exe` с помощью PyInstaller — его можно запускать на
компьютерах без Python.
